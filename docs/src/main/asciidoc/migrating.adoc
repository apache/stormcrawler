== Migrating to 4.0.0

This section covers upgrades from 3.7.0 to 4.0. Each entry says who is
affected and, where needed, what to do. For other changes, see the release
notes. When upgrading from an earlier 3.x release, also read the release notes
of the versions in between.

* <<Upgrading>> applies to every crawler.
* <<Crawler configuration and behaviour>> applies to crawlers which use the keys
or modules named in its entries.
* <<Stored data>> applies to crawls which reuse data stored before the upgrade.
* <<Metrics and output formats>> applies to crawls whose metrics or output are
read by other tools.
* <<Custom Java code>> applies to projects with their own Java classes.

=== Upgrading

==== Upgrade steps

. If a crawl using the SQL module may need a rollback to 3.x, back up its status
table first (see <<Stored data>>).
. Upgrade the Storm cluster and its JDK, and update the project, as described
in <<Java and Storm>> and <<Project changes>>.
. Fix the build of custom classes, as described in
<<Custom Java code>>.
. Review the configuration against
<<Crawler configuration and behaviour>>.
. Start the topology. These fail at startup: an invalid IP filter rule, Tika
configuration or jsoup XPath expression, and a `FastURLFilter` rule without a
type. If `http.basicauth.hosts` or `http.custom.headers.hosts` is empty, those
credentials are not sent and a warning is logged.
. After the first crawl, compare a few URLs from the cases below with their
records from before the upgrade: fetch status, extracted content and stored
keys. These cases change what is fetched, parsed or stored without stopping the
topology. The list is not complete.
* robots.txt redirects to another host, and robots.txt files over 512 KiB
* redirects on sites whose robots.txt lists sitemaps
* hosts with invalid certificates or non-public IP addresses
* `file:` URLs
* cookies without a `Domain` attribute
* sitemaps without `isSitemap` in their metadata
* sitemaps and feeds with many entity references
* pages with a charset declared in the HTTP `Content-Type`
* Tika metadata keys, embedded documents and the MIME type whitelist
* custom JSoupFilters, which now also run on Tika output
* stored URL forms and host keys
* text extracted by the AI module with its default prompt
* `HostURLFilter` with `ignoreOutsideDomain: true`
* custom URL filters which throw exceptions
* overrides of the removed `addHeadersToRequest(Request.Builder, Metadata)`

==== Java and Storm

StormCrawler 4.0 requires Java 25 and Apache Storm 3.2.0, so the Storm cluster
and its JDK must be upgraded too. The changes to the cluster are described in
the release notes of
link:https://storm.apache.org/2026/07/22/storm300-released.html[Storm 3.0.0],
link:https://storm.apache.org/2026/09/12/storm310-released.html[Storm 3.1.0] and
link:https://storm.apache.org/2026/11/10/storm320-released.html[Storm 3.2.0].

==== Project changes

Projects generated from a 3.x archetype need these changes in their `pom.xml`:

* Set `stormcrawler.version` to `4.0.0` and `storm.version` to `3.2.0`.
* Set the `source` and `target` of the compiler plugin to `25`.
* If the project depends on `stormcrawler-tika`, add an `AppendingTransformer`
to the shade plugin for each index file of Tika 4. Tika spreads these files
over several jars: `META-INF/extensions.idx` and, under `META-INF/tika/`,
`detectors.idx`, `encoding-detectors.idx`, `language-detectors.idx`,
`metadata-filters.idx`, `parse-context.idx`, `parsers.idx`, `renderers.idx` and
`translators.idx`.
+
[source,xml]
----
<transformer
    implementation="org.apache.maven.plugins.shade.resource.AppendingTransformer">
    <resource>META-INF/tika/parsers.idx</resource>
</transformer>
----
* If the project declares `tika-parsers-standard-package`, add
`<type>pom</type>` to that dependency. Tika 4 publishes it as a POM.

A `pom.xml` generated by the 4.0 archetype contains all of these changes and
can be used for comparison. The `crawler.flux` of a project generated from a 3.x
archetype also needs the status stream connection described in <<Topologies>>.

These modules change:

* `stormcrawler-opensearch-java` is merged into `stormcrawler-opensearch`, which
now uses the OpenSearch Java client. Users of either module should follow
link:https://github.com/apache/stormcrawler/blob/main/external/opensearch/README.md#upgrading-from-versions-before-40[Upgrading from versions before 4.0]
in the OpenSearch README.
* The Selenium module is removed. Use the
xref:configuration.adoc#_playwright[Playwright] module instead.
* The AWS module no longer supports CloudSearch. It keeps
the S3 bolts. Index into another backend, for instance
xref:configuration.adoc#_opensearch[OpenSearch].

=== Crawler configuration and behaviour

==== HTTP and access to resources

The keys below are described in
xref:configuration.adoc#_configuration_options[Configuration Options].

* A robots.txt redirect is now followed only within the same scheme, host and
port, or from http to https on the same host with default or unchanged ports.
Other redirects, for instance from `example.com` to `www.example.com`, are
refused. The URLs of the host then end as `ERROR` with `error.cause` set to
`robots.txt`, and a warning starting with `Robots for` is logged. With the
default `fetchInterval.error: -1` they are never fetched again. Before the first
crawl, set `http.robots.redirect.crossorigin.allow: true` to follow such
redirects, or `http.robots.redirect.refused.allow: true` to crawl these hosts
without robots.txt rules.
* `org.apache.stormcrawler.protocol.httpclient.HttpProtocol` is removed. If
`http.protocol.implementation` or `https.protocol.implementation` names it, use
the default, `org.apache.stormcrawler.protocol.okhttp.HttpProtocol`.
* With OkHttp, `http.trust.everything` now defaults to `false` instead of
`true`, and the new `http.verify.hostnames` defaults to `true`. Fetches from
hosts with an invalid certificate end as `FETCH_ERROR`, with the TLS exception
in `fetch.exception`. For self-signed or expired certificates, set
`http.trust.everything: true`. For a valid certificate issued to another host
name, set `http.verify.hostnames: false`. Either setting stops credentials from
being sent, as described in the next entry.
* With OkHttp, basic auth, credential headers and cookies are now sent only over
HTTPS with the certificate and host name checks on. Credential headers are
`Authorization`, `Proxy-Authorization`, `Cookie`, `X-Api-Key` and those listed
in `http.credentials.headers`. To send credentials anyway, set
`http.credentials.allow.insecure: true`.
* Basic auth is now sent only to the hosts listed in `http.basicauth.hosts`,
and credential headers only to those listed in `http.custom.headers.hosts`,
instead of every host.
Crawls which set `http.basicauth.user` or credential headers in
`http.custom.headers` must list their hosts, each subdomain separately. If a
list is empty, those credentials are not sent and a warning is logged at
startup.
* `http.filter.ipaddress.exclude` now blocks loopback, private, link-local,
multicast and other non-public addresses by default, for OkHttp and Playwright.
With OkHttp, a blocked fetch ends as `FETCH_ERROR` and logs
`Blocked connection to IP address`. To crawl an intranet or local servers,
override the key, for instance with `""`. Setting only
`http.filter.ipaddress.include` does not undo the default. An invalid rule now
fails the topology at startup instead of being ignored. See
xref:configuration.adoc#_ip_address_filtering[IP Address Filtering].
* `protocols` now defaults to `http,https` instead of `http,https,file`. To
crawl a local corpus, add `file` and set the new `file.protocol.root`. Without
it, `file:` URLs end as `FETCH_ERROR` and a warning starting with
`Refusing to read` is logged.
* `http.robots.content.limit` now defaults to 524288 bytes instead of no limit,
so a robots.txt larger than 512 KiB is truncated. To read larger files, raise
the limit. The value `-1`, which meant no limit in 3.x, now means the value of
`http.content.limit`, 65536 bytes in the archetype configurations.
* With `http.allow.redirects: true`, OkHttp now runs each redirect hop through
the URL filters and follows at most `http.allow.redirects.max` hops, 5 by
default. To follow longer chains, raise `http.allow.redirects.max`.
* With `http.use.cookies: true`, a cookie without a `Domain` attribute is now
sent only to the host which set it, and only when `protocol.set-cookie-origin`
is present next to `protocol.set-cookie`. Add `protocol.set-cookie-origin`
wherever `protocol.set-cookie` is listed in `metadata.transfer` or
`metadata.persist`.
* A sitemap without `isSitemap` in its metadata, such as a seed, is now detected
by its content only when the new `sitemap.sniffContent` is `true`. Otherwise
the URLs it lists are not added. Set `isSitemap=true` in the metadata of such
seeds, or set `sitemap.sniffContent: true`.
* A sitemap which fails to parse now ends as `FETCH_ERROR` instead of `ERROR`,
and `isSitemap` is removed from its metadata. Records already set to `ERROR`
are not changed.
* With `sitemap.discovery: true` and the `SitemapFilter` URL filter, as in the
archetype configurations, redirect targets, including meta refreshes, on sites
whose robots.txt lists a sitemap are now kept instead of being dropped, so more
URLs are discovered.
* With Playwright, setting `http.proxy` no longer disables certificate
validation. Behind a TLS-intercepting proxy, set
`playwright.ignore.https.errors: true` or install the proxy CA in the browser
image.
* When set, `fetcher.thread.timeout` now also applies to the robots.txt lookup.
A lookup which times out is treated as failed, and the URLs of the host are
fetched without robots.txt rules while the failure is cached, one hour by
default with `robots.error.cache.spec`. Set the timeout above the time a
robots.txt fetch takes. A value above `topology.message.timeout.secs` is lowered
to it, and a warning is logged.

==== Parse filters and XML

* The ParseFilters `org.apache.stormcrawler.parse.filter.XPathFilter`,
`LDJsonParseFilter` and `LinkParseFilter` are removed. Remove their entries from
`parsefilters.json` and add the classes of the same names in
`org.apache.stormcrawler.jsoup` to `jsoupfilters.json`. The 3.x archetype
configurations already list the jsoup `XPathFilter` and `LinkParseFilter`
there.
Custom ParseFilters are covered in
<<ParseFilters without a DOM>>.
* Expressions of the removed `XPathFilter` must be rewritten for the jsoup one,
which selects what to extract with a suffix of the expression instead of a
wrapper function. `string(//X)` becomes
`//X/tidyText()`, and `serialize(//X)` becomes `//X/html()`, which returns the
inner HTML of the element. The suffixes `/allText()` and `/@attribute` are also
available.
* The jsoup `XPathFilter` now compiles its expressions at startup with the JDK
XPath engine. An invalid expression fails the topology instead of being logged
for each page, and jsoup's `W3CDom.XPathFactoryProperty` is ignored.
* The jsoup `XPathFilter` now skips blank values and tries the next expression
for the same key. With the archetype configurations, an empty `<title>` falls
back to the `title` meta tag, and blank descriptions or keywords are no longer
stored.
* `CommaSeparatedToMultivaluedMetadata`, which the archetype configurations
apply to `parse.keywords`, now keeps at most 128 values per key and logs a
warning when it drops more. To keep more, set its `maxTokens` parameter.
* Charset detection now reads the charset of the HTTP `Content-Type` header,
which it missed in 3.x with the default `protocol.md.prefix`. When the header
and the meta tag declare the same charset, it is used without detection. When
only the header declares one, it guides the detection. When they differ, the
meta tag guides it, as in 3.x. The decoded text of these pages can change.
* `DebugParseFilter` is removed, with no replacement. Remove its entry from
`parsefilters.json`.
* Core no longer depends on Xerces. Sitemaps, feeds and the XML-based documents
parsed by Tika, such as OpenDocument files, now use the JDK parser. It fails on
documents with many entity references, such as escaped ampersands in URLs. See
xref:configuration.adoc#_parsing[Parsing] for the JVM options that lift its
limits.

==== Tika 4

* Tika 4 reads its configuration from JSON only. The default file is now
`tika-config.json` instead of `tika-config.xml`.
Convert a custom configuration as described in
link:https://tika.apache.org/docs/4.0.x/migration-to-4x/migrating-to-4x.html[migrating to Tika 4],
and set its name with `parser.tika.config.file`. The `parse.tika.config.file`
key of the 3.x archetype configurations was never read and can be removed. An
invalid configuration fails the bolt at startup.
* The
link:https://tika.apache.org/docs/4.0.x/migration-to-4x/metadata-changes-4x.html[metadata renames of Tika 4]
change the keys which the ParserBolt stores with the prefix `parse.`. For
example, `parse.resourceName` becomes `parse.tk:resource-name`. The `dc:*` keys
are unchanged. Update `indexer.md.mapping`, filters and other code reading these
keys. A wildcard mapping such as `parse.*` produces different field names. The
`parse.title`, `parse.keywords` and `parse.description` keys of the archetype
configurations come from the JSoupFilters, and their names are unchanged.
* The Ogg, Vorbis, Opus, FLAC, Speex and Theora parsers are now part of Tika. If
a Tika configuration names the classes under `org.gagravarr.tika`, use the Tika
parsers instead. They are registered as `ogg-parser`, `vorbis-parser`,
`opus-parser`, `flac-parser`, `speex-parser` and `theora-parser`.
* Embedded documents are now parsed only when `parser.extract.embedded` is
`true`. With the default `false`, their text no longer ends up in the parent
document. To keep it, set `parser.extract.embedded: true`.
* `parser.mimetype.whitelist` is now matched against the type detected from the
content instead of the HTTP `Content-Type`. Content whose type cannot be
detected is `application/octet-stream`, and it is skipped unless the whitelist
includes it. To keep parsing such content, add `application/octet-stream` to the
whitelist.
* The ParserBolt now also runs the JSoupFilters of `jsoup.filters.config.file`
on the XHTML produced by Tika. The `XPathFilter` of the archetype
configurations also sets `parse.title` for these documents when Tika reports a
title.

==== Topologies

The querying spouts of the OpenSearch, Solr, SQL and URLFrontier modules now
mark rows whose URL scheme is not in `protocols` as `ERROR`. They send them on
the `status` stream. Connect the spout to the status updater on that stream, as
the 4.0 archetype `crawler.flux` files do. Without it, these rows are queried
again and again.

[source,yaml]
----
  - from: "spout"
    to: "status"
    grouping:
      type: FIELDS
      args: ["url"]
      streamId: "status"
----

In Java, the equivalent is
`.fieldsGrouping("spout", Constants.StatusStreamName, new Fields("url"))` on the
status updater bolt.

==== Stored data

Some URLs and keys stored by 3.x get a different form in 4.0. Stored records
are not rewritten. If a URL discovered again gets a different stored form or
storage key, an additional record can be created and the URL may be fetched
again. No configuration change is needed. The URLs affected are:

* URLs with a query which `BasicURLNormalizer` rewrites because of an uppercase
scheme or host, an IDN host or path escapes. The `?` and the query after it
are now kept, instead of the `?` being escaped to `%3F` and the query becoming
part of the path.
* URLs with a `/` in a query value, such as `?sid=01/10&mode=thread`. The
normalizer no longer turns the `&` after the last `/` into a second `?`.
* URLs whose query contains `;`, when `removeHashes` is `true` or
`queryElementsToRemove` is not empty. The archetype configurations set
`removeHashes: true`. The query is now split on `&` only, so `?a=1;b=2` is
written as `?a=1%3Bb%3D2` instead of `?a=1&b=2`. A parameter after a `;` is no
longer removed.
* URLs whose host has uppercase letters, percent-escapes, a trailing dot or
Unicode characters. The politeness queues, partition keys and robots.txt cache
now use the host lowercased, percent-decoded, without the trailing dot and in
punycode. With `opensearch.status.routing` or with URLFrontier, the next update
of such a URL can be stored under the new key, next to the old record.
* URLs with a Unicode host. The OpenSearch `key` field and the value of
`DomainParseFilter` are now in punycode. Crawls with `hostIDNtoASCII: true` in
`BasicURLNormalizer`, as in the archetype configurations, already store
punycode hosts for URLs added since it was set.

The SQL `StatusUpdaterBolt` now writes the metadata column in an escaped form
behind a `v1` marker. Rows written by 3.x are read as before, so no migration is
needed. After a rollback to 3.x, a value written by 4.0 which contains a
backslash, a tab, a line break or `=` is read with its escape sequence, for
instance `a\=1` instead of `a=1`. If a rollback may be needed, back up the
table before upgrading.

With a wildcard mapping in `indexer.md.mapping`, such as `parse.*`, the SQL
`IndexerBolt` now skips metadata keys which are not made of letters, digits and
`_` only, and logs them, instead of failing the insert.

The Solr `StatusUpdaterBolt` no longer replaces the record of a URL already in
the `status` collection when the URL is discovered or injected again. Seeds
injected again keep their status and `nextFetchDate`. To fetch known URLs
again, change their `nextFetchDate` in the collection. This needs the
`updateLog` of `solrconfig.xml`, which the `status` configset has had since
3.5.0. A collection created from an older configset still has its records
replaced.

==== Metrics and output formats

* With Metrics V2, the status updater metrics `cache.hits` and `cache.misses`
are now cumulative counters instead of values reset on every read. Dashboards
which plotted their values must plot their rate instead, for instance with
`rate()` in Prometheus. With Metrics V1 they are reported as a single `cache`
metric, which the bundled metrics consumers flatten to `cache.hits` and
`cache.misses`.
* Storm 3.2.0 ignores `storm.metrics.reporters`, and Nimbus logs a warning when
a topology sets it. Rename it to `topology.metrics.reporters`. The Javadoc of
the 3.x `MetricsReporter` classes of the OpenSearch, Solr and SQL modules used
the old key.
* In WARC records, `WARC-Protocol` is now repeated for each value and uses
lowercase identifiers, for example `tls/1.3` instead of `TLS_1_3`. The cipher
suite is written to a new `WARC-Cipher-Suite` header. Line breaks in metadata
values are replaced by spaces, and invalid keys in `warc.metadata.keys` are
dropped with a warning. Tools which parse `WARC-Protocol` must accept a
repeated header and lowercase values.
* The LLM text extraction of the AI module has a new default prompt. The
extractor now keeps only the `<content>` element of a reply which has one.
Crawls with the default prompt get differently extracted text. See the
link:https://github.com/apache/stormcrawler/blob/main/external/ai/README.md[AI module README]
for the prompt placeholders.

==== Removed configuration keys

These keys are no longer read and can be removed:

* `parser.uppercase.element.names`, with no replacement.
* `selenium.*`, replaced by the keys of the Playwright module.
* `navigationfilters.config.file`. Playwright page actions are declared in
`playwright.page.actions.config.file`.
* `cloudsearch.*`, with no replacement.
* `opensearch.sniff` and `opensearch.<type>.sniff`. List every node in
`opensearch.<type>.addresses` instead, or put a load balancer in front of the
cluster.
* `opensearch.responseBufferSize` and `opensearch.<type>.responseBufferSize`,
with no replacement.

The OpenSearch bolts and metrics consumers which write through
`AsyncBulkProcessor` log a warning at startup when one of these `opensearch`
keys is set.

==== URL filters

* A URL filter which throws an exception now rejects the URL instead of letting
it through. The log shows `URL filter <class> threw exception`.
* A `FastURLFilter` rule without a type now fails at startup with
`FastURLFilter rule does not start with a known type`. Start each rule with
`DenyPath`, `DenyPathQuery`, `AllowPath` or `AllowPathQuery`.
* `HostURLFilter` now applies `ignoreOutsideDomain: true` also when
`ignoreOutsideHost` is not set. Such a configuration drops outlinks to other
domains. To keep them, remove `ignoreOutsideDomain`.
* `SelfURLFilter` now compares the path and query of a link with those of the
page case-sensitively. A link or redirect which differs from the page URL only
in their case, such as from `/a.html` to `/A.html`, is no longer dropped.

=== Custom Java code

==== ParseFilters without a DOM

ParseFilters no longer receive a DOM. The parse filters shipped with
StormCrawler which used it are covered in
<<Parse filters and XML>>.

* `ParseFilter.filter` now takes `(String url, byte[] content, ParseResult parse)`.
The `DocumentFragment` argument and `needsDOM()` are removed. Remove them from
custom ParseFilters. Move logic which read the DOM to a JSoupFilter, which gets
the jsoup document.
* `DocumentFragmentBuilder`, the Tika module's `DOMBuilder` and
`RobotsTags.extractMetaTags(DocumentFragment)` are removed. Use the jsoup
document, and `RobotsTags.extractMetaTags(String)` with the content of the
robots meta tag.

==== Other API changes

* The HttpClient protocol is removed. Port its subclasses to the OkHttp
protocol.
* The Selenium module is removed. Rewrite custom NavigationFilters, for instance
as Playwright page actions declared in `playwright.page.actions.config.file`.
* `ParseResult.get(String)` is removed. Use `getOrCreate(String)` to add a
sub-document or `getIfPresent(String)` to read one. The parser bolts no longer
emit a sub-document whose content, text and metadata are all empty.
* Both overloads of `CookieConverter.getCookies(...)` now return immutable
`org.apache.stormcrawler.util.CookieConverter.Cookie` records instead of
HttpClient cookies. Update the cookie type import and use the record accessors
`name()`, `value()`, `domain()`, `path()`, `secure()` and `expiry()`. The expiry
is a `java.time.Instant`, or `null` for a session cookie.
* The OkHttp `HttpProtocol` no longer has
`addHeadersToRequest(Request.Builder, Metadata)`. Subclasses which override it
must override
`addHeadersToRequest(Request.Builder, Metadata, boolean sendCredentials)`
instead. An override of the old method without `@Override` still compiles, but
StormCrawler no longer calls it.
* The static methods `WARCRecordFormat.getDigestSha1(byte[])` and
`getDigestSha1(byte[], byte[])` are removed. Use the instance methods
`getDigest(byte[])` and `getDigest(byte[], byte[])`. They apply the algorithm
passed to the constructor, SHA-1 by default.
* `CharsetIdentification.getCharset` and `getCharsetFast` now require a fourth
argument: the prefix of the response headers in the metadata, with its
separator. Pass `"protocol."`, for instance, or `""` when the headers are not
prefixed.
* `URLBuffer.getInstance(Map)` and the static
`Configurable.configure(Map, JsonNode, Class, String)` are removed. Use `URLBuffer.createInstance(Map)` and
`Configurable.createConfiguredInstance(String, Class, Map, JsonNode)`, which
takes the name of the calling class first.
* Code using Tika classes directly must follow the
link:https://tika.apache.org/docs/4.0.x/migration-to-4x/migrating-to-4x.html[Tika 4 migration guide].

==== Dependencies no longer provided

Core no longer depends on the HttpComponents libraries HttpClient and HttpCore.
The few classes it used are copied into
`org.apache.stormcrawler.internal.httpcomponents`, which is for internal use
only. Code which uses HttpComponents classes and relied on core to bring them
in must declare its own dependency. An example is `org.apache.http.HttpHeaders` from HttpCore 4, for
the names of the response headers in the metadata.

These dependencies are no longer brought in transitively:

* Xerces
* the OpenSearch REST clients, sniffer and server jar
* Selenium
* the HBase client libraries, through the WARC module

Code importing their classes must declare its own dependency.
